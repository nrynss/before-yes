## Attacks on the fix
- **Gatherer notes.** `Gathered.Notes` (the App Store and Tavily error text) is only ever appended to. Nothing reads it outside `gather.go`, and it is not in `Evidence`, `Stats` or the card. It is never logged or stored.
- **Alternatives run on visitor keys.** `work` runs `FindAlternatives` and `CheckAlternatives` on `adm.p`, the visitor copy. That copy has the visitor's Tavily and model clients and `Checks` nil, so nothing is booked on our pool. When an alternative fails, its error is dropped: it changes only `Status` and the `beats` decision. No error text gets into `Alternative` or the card.
- **Evidence cache.** No `Classifier` is set, so Keel never stores a refusal payload, which would be `err.Error()`. This also means a visitor with a bad key cannot poison the title for other users. Successful evidence holds no key, and the cache key does not change.
- **Logging.** `internal/model`, `internal/tavily` and `internal/pipeline` do not log. Keel's job runner logs only store faults, and it gets the scrubbed error. Progress messages are fixed strings.
- **Resume.** `JobKind` is `Idempotent: false` and has no `Resume`. So a visitor job interrupted by a restart is never rerun on our keys, and never rerun uncapped.
- **Timeouts and context errors that include URLs.** These are covered by the wrapped-chain probe. Keys never go in a URL anyway: Tavily uses a bearer header.
- **Cap lifecycle under `-race`.** The hold is reserved before `StartKind`. `Done` runs on a card. `Fail` runs on an error, on a panic (through the deferred `ended` guard) and when the job does not start. `TestFailedCheckReleasesHold` and the race probe both hold.
- **Shared-meter rule.** `checkCapWiring` is unchanged and still pinned by `TestCapWiringSharesOneMeter`. The main check is reserved once, and alternatives go through `Pipeline.Checks`.
- **Scope.** The diff touches `internal/server/byok*.go`, the noted `checks.go` lines, one line in `docs/api.md`, PHASE-4 and the round-1 file. It does not touch `tools/eval/` or `testdata/eval/`.
- **No dates in the dev-diary.** The branch's dev-diary diff adds no dates or times. One date already on `main` (`t2.3b-round1.md`, line 3, from commit `a9eb2d4`) is outside this task. I am reporting it to the orchestrator so it can close it as documentation.

## Findings

### Low (accepted)
- **L1: the panic log line redacts only the raw, JSON and URL forms.** `redact(fmt.Sprint(v))` leaves a base64 or case-folded key in the `visitor check panicked` log line. The probe confirmed this. I accept it: no code path base64-encodes or case-folds a key, no current panic carries a key, and the stored record is the fixed message. If this ever changes, the fix is to log the panic's type only.
- **L2: a panic in a reader goroutine (`read.go`) is outside `wrap`'s recover.** A panic there would crash the process and print to stderr without redaction, on any job. Panics in goroutines a job starts itself are a pre-existing pipeline property. They are outside T4.5's `owns`, and none carries a key. A Go stack trace prints arguments as words, not string contents. I accept this. It could become a P6 hardening note.
