## Task requirements verification

### 1. Wire ID formatting
- Public check IDs strictly match `"j_" + [0-9a-f]{32}` (`^j_[0-9a-f]{32}$`).
- Public card IDs strictly match `"c_" + [0-9a-f]{32}` (`^c_[0-9a-f]{32}$`).
- `GET /api/checks/{id}` and `GET /api/checks/{id}/events`:
  - Require `"j_"` prefix and validate that the remainder satisfies `id.Valid`.
  - Bare hex (`^[0-9a-f]{32}$`), cross-prefixed (`c_...`), and malformed IDs return 404 `not_found` before executing any runner or database query.
- `GET /api/cards/{id}`:
  - Requires `"c_"` prefix and validates that the remainder satisfies `id.Valid`.
  - Bare hex, cross-prefixed (`j_...`), and malformed IDs return 404 `not_found` before executing any store query.

### 2. POST /api/checks
- Body decoding is bounded to 4096 bytes via `io.LimitReader(r.Body, 4096)`.
- Input validation: empty/bad title, missing body, or age outside `[2, 17]` returns 400 `invalid_request` with the exact contract message `"title is required and age must be between 2 and 17"`.
- Card cache hit: returns 200 `{"card_id": "c_<hex>"}` immediately without starting a job or spending budget.
- Concurrency limit: when check runner reaches its concurrency limit (`job.ErrLimit`), responds with HTTP 503 `busy`, `Retry-After: 20` header, and body detail `{"retry_after_seconds": 20}`.
- Check started: starts Keel job of kind `"check"` and answers 202 `{"check_id": "j_<hex>"}`.

### 3. Check job execution
- Non-idempotent: `NewRunner` sets `Idempotent: false` for kind `"check"`. Across server restarts, unfinished jobs are marked `interrupted` and never resumed or restarted automatically.
- Progress reporting: reports progress via `job.Progress` across stages `gather`, `read`, `judge`, and `alternatives` with current/total counts when counting reviews and detail payload `{"message": "..."}`.
- Evidence cache integration: reuses `EvidenceCache.Collect` for single-flight deduplication and source caching.
- Decisions & alternatives: evaluates verdict with `Pipeline.Decide`; for `no` or `yes_with_settings`, runs `FindAlternatives` and `CheckAlternatives`, persisting via `Cards.PutWithAlternatives` or `Cards.Put`.
- Failure mapping: maps failure causes to `job.Failure{Code: ...}` so that the stream terminal error event and stored job record carry matching Before Yes codes:
  - `cost.ErrOverBudget` -> `budget_exhausted` with `detail.pool` (`token_factory`, `tavily`, or `daily_checks`).
  - `pipeline.ErrNoSources` -> `no_sources`.
  - default/other -> `check_failed`.

### 4. GET /api/checks/{id}
- Reads job state from `Runner.Result`:
  - `running` -> 200 `{"id": "j_...", "status": "running"}`.
  - `queued` -> 200 `{"id": "j_...", "status": "queued"}`.
  - `done` -> 200 `{"id": "j_...", "status": "done", "card_id": "c_..."}`.
  - `error` -> 200 `{"id": "j_...", "status": "error", "code": code, "message": fixedMsg, "detail": detail}`.
  - `interrupted` -> 200 `{"id": "j_...", "status": "interrupted", "code": "check_failed", "message": "The server restarted during this check. Ask again; sources already read are reused."}`.
  - Unknown ID -> 404 `not_found` with message `"no such check"`.

### 5. GET /api/checks/{id}/events
- Validates `"j_"` check ID, verifies job existence via `Runner.Result` (returning 404 for unknown check), and serves topic over SSE via `Broker.ServeTopic`.
- Emits `progress` events and terminal `done` or `error` event adhering to Keel wire vocabulary (`testdata/contracts/api/events-done.txt` and `events-error.txt`).

### 6. GET /api/cards
- Returns 200 `{"cards": [...]}` with up to 12 recent card summaries.
- Empty store returns `{"cards": []}`.
- Each entry formats `id` with `"c_"` prefix, matching `testdata/contracts/api/get-cards.json`.

### 7. Seam for T4.5
- Declares `Checks` interface on `Server` (`BeginCheck(ctx, ref) (*spend.Check, error)`) without wiring into `startCheck`.
