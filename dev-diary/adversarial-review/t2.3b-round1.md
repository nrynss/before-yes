## Checked and passing

- **Scope.** `git diff main...review-t2.3b --name-only`: `dev-diary/PHASE-2-clients.md` (T2.3b `status:` `claimed:impl-t2.3b` to `in-review`, nothing else) and `internal/appstore/live_test.go` (819 lines added, 1 line changed elsewhere: 820 + / 1 -, matching "about 820"). `live_test.go` is exactly the task's `owns`. No `testdata/`, no committed response bodies, no `go.mod`/`go.sum` change; the probe reads the T2.3 fixtures (`mustFixture`) and fetches live bodies into memory only, never to disk.
- **Build tag.** First line is `//go:build live`. `./tools/check.sh` exits `PASS: tools/check.sh` without the tag, so the probe is not in the gate (the gate output shows no `TestLive*`); `go vet -tags live ./...` and `go build -tags live ./...` succeed.
- **Politeness.** One search plus at most `MaxPages` (10) sequential review pages per storefront, so at most 22 requests per run; the client's own loop reads one page at a time and stops at the first empty page, with a 30 s per-request timeout and a 4 minute context deadline. No goroutines, no retry loop, no tight loop. There is no inter-page pause, but pages are sequential and a full run is bounded and brief; below the finding bar.
- **Secrets.** Through `/tmp/claude-1000/envwrap.sh`, each of the four values in the main checkout's `.env`, never printed: `git grep -lF` matches 0 files in the worktree and 0 in the branch tree, for every value. The probe reads no `.env` or `before-yes.toml`.
- **Honest design.** Raw bodies are kept by a recording transport and the client's read is checked against them field by field (review text is never printed); the second storefront, `gb`, is justified in the file header (the brief names no parent country).
- **Search half works live.** `us` search returned the 3 recorded hits and the Roblox hit equals the T0.4 capture in id, name, seller, seller URL, store URL and age rating, with the same 44 raw keys. `gb` returned 5 hits; the only field differing is the store URL's storefront segment (`/gb/` for `/us/`), as expected.

## Out of scope

- **Project risk for the orchestrator.** If the review feed is dead or gated for popular apps, T3.x's gather step has no review source for the demo, and the brief's "up to about 500 recent reviews per country" assumption fails. The recorded fixture is the only evidence of the feed's shape. Worth an early decision before the pipeline depends on it, and a look at whether the feed still serves any app (the probe could take a second title).
