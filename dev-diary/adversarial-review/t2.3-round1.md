Attempts that failed to break it:

- Trying to drift the running index: forcing the feed to lead page 1 with a content-less app entry still put page 2's first review at index 51, because the index counts reviews only. No captured page has an app entry (all 40 lead with a review), so the skip rule costs nothing on real data.
- A page whose only entry is content-less does not stop the read — it continues to the last page. No captured page is like that, and the spec's "empty page" is the empty `entry` member, which does stop it. Recorded as behaviour, not a defect.
- `Client` has exported `BaseURL`/`Country` but an unexported `http` field set only by `New`, so a literal `&Client{}` would panic rather than error. No caller constructs it that way; below the finding bar.
- `Reviews`'s doc does not spell out that `pages <= 0` means `MaxPages`; its only planned caller documents the same meaning, so nothing is misled.
- No retry, pacing or User-Agent handling — none is asked for here, and Apple's live tolerance is T2.3b's measurement.
