## Findings

### H1. Thin / uncacheable evidence is cached when an expired entry already exists in the store
In `internal/server/cache.go` (`Collect`), `maker` detects whether `p.Collect` cached the evidence by checking `c.store.Get(ctx, key)` for `cache.ErrNotFound`:
```go
_, getErr := c.store.Get(ctx, key)
if errors.Is(getErr, cache.ErrNotFound) {
    return cache.Result{}, uncacheableEvidenceError{ev: ev, hit: pHit}
}
```
`p.Collect` intentionally omits calling `p.Cache.Put` when evidence is thin or has source failures (`rd.Failed > MaxFailedChunks` or `len(g.Failures) > 0`). However, `c.store.Get(ctx, key)` queries the raw persistent SQLite store, which retains rows across expiry. If the title was ever checked previously and its entry has since expired past `MaxAge`, `c.store.Get` returns the expired row with `getErr == nil`.

Because `getErr` is not `cache.ErrNotFound`, `maker` does not return `uncacheableEvidenceError`. Instead, `maker` returns a valid `cache.Result`, which Keel's `cache.Cache.GetOrMake` writes to `c.store` via `c.storeResult` with `CreatedAt = now`. This permanently caches thin evidence for the full `MaxAge` (7 days), violating the requirement: "Thin/uncacheable evidence not stored in cache but shared with flight joiners" and "A failed collect is never cached, nor is one where more than MaxFailedChunks reader chunks failed, nor one where a source call errored."

**Pin:** Throwaway probe test:
1. Populate `EvidenceCache` with a valid, cacheable collect for "Roblox".
2. Advance test clock by 25 hours (past 24h `MaxAge`), confirming `ec.Get` returns `ok=false`.
3. Collect again with `failExtract = true` (generating `Gathered.Failures` so `p.Collect` skips `p.Cache.Put`).
4. Read the store: `store.Get` row timestamp is updated to `now` (age 0s), and subsequent `ec.Get(ctx, key)` returns `ok=true` with the thin evidence payload.

### M1. Unbounded in-memory map leak in `EvidenceCache.activeFlights`
`EvidenceCache` maintains `activeFlights map[string]*flightState`. Whenever `maker` executes, it records `c.activeFlights[key] = st` under `c.mu`. However, keys are never removed from `activeFlights` (`delete(c.activeFlights, key)` is never called anywhere in the codebase).

In a long-running server (`cmd/before-yes serve`), every distinct title, storefront, and reader model checked indefinitely retains a map entry.

**Pin:** `git grep -n "delete" internal/server/cache.go` yields 0 matches. In a probe test issuing sequential checks across 100 distinct titles, `len(c.activeFlights)` reaches 100 and never decreases.

### L1. Redundant double-write to SQLite store on cache miss
When `p.Collect` gathers cacheable evidence, it invokes `p.Cache.Put(ctx, key, ev)`, which serializes `ev` and writes it to `c.store`. Then `p.Collect` returns to `maker`, which marshals `ev` a second time into `cache.Result.Payload`. Finally, Keel's `cache.Cache.load` executes `c.storeResult`, calling `c.store.Put` a second time with the identical key and payload.

While functionally inert, this causes redundant JSON serialization and duplicate disk writes to SQLite on every fresh collect.

**Pin:** Instrument `cache.Store.Put` in a probe test: a single `ec.Collect` on a cold title invokes `store.Put` exactly twice with the same key.

## Checked and clean

- **Keel ID validation:** `cards.Store.Get` validates `id.Valid(cid)` and rejects invalid IDs with `cards.ErrNotFound` before executing any SQL query. Verified against a closed SQLite database where invalid IDs return `ErrNotFound` without querying the connection.
- **Card store migrations & namespaces:** `cards.Open` runs migrations under namespace `beforeyes_cards`. It coexists cleanly in a single SQLite database file alongside Keel cache (`cache`, `evidence`), job (`job`), and spend meter (`cost_model`, `cost_tavily`, `cost_checks_daily`) stores without collision. Reopening an existing database is idempotent.
- **Card store operations:**
  - `Put` mints 32-hex Keel IDs via `id.New()`, updates the stored card's JSON `id` attribute, and preserves the caller's struct unmodified.
  - `PutWithAlternatives` is atomic: failure of any insert rolls back the entire batch. Checked alternatives are remapped to fresh Keel IDs, dangling links are dropped, and invalid or duplicate IDs are refused with `ErrInvalid`.
  - `Latest` searches newest card by folded title key, age, checklist version, and `since` timestamp, using the `cards_lookup` index.
  - `Recent` orders by `created_at DESC, seq DESC` partitioned by `title_key, age`, field-for-field matching `testdata/contracts/api/get-cards.json`.
- **CardCache:** `CardCache.Fresh` correctly folds title casing and whitespace, queries `cards.Latest` with checklist version and `MaxAge`, and handles store errors safely without masking them as misses.
- **Single-flight deduplication:** Concurrent identical checks execute only 1 gather and 1 reader call. The flight leader receives `hit = false` while concurrent joiners receive `hit = true`.
- **Offline operation:** All tests run strictly offline against fixtures and fakes. No live network calls or credentials required.
