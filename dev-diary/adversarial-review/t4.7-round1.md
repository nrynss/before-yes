## Findings

### M1. The view can show a lower read count after a reconnect (`web/src/lib/progress/Progress.svelte`)
Chaaya's `JobStream` opens the stream first, then calls `fetchState`, then applies frames as they arrive. `keep()` runs inside `fetchState` and sets `savedAt = stream.events.length`. When the stream reconnects with `Last-Event-ID`, Keel replays the missed frames. Any replayed frame that lands after `keep()` has `latestIndex >= savedAt`, so `live` replaces the saved snapshot even though the snapshot is newer. Example: the snapshot reads 7 of 9, then the replay delivers 5 of 9 and 6 of 9. The parent sees 7, then 5, 6 and 7 again. Chaaya's own `#catchUp` refuses to move counted progress backward, but this view's override does not apply the same rule. The server keeps its counts in order, but the page can still show them going backwards. The reconnect spec only pushes a newer stage (`judge`), so it misses this case.
Fix: prefer a stream frame over `saved` only when it is in a later stage, or in the same stage with `current >= saved.current`. Add a spec that replays an older read count after the snapshot.

### L1 (accepted). A panic in the progress hook is not recovered
`report` runs inside the reader's chunk goroutines, under `progMu`. If the hook panicked, the process would crash. Today the only hook is `work`'s, which calls Keel's `report`, so the risk is low. The hook also runs under a lock and slows each chunk by one store write, which is acceptable. Cancellation is safe: a cancelled chunk still counts, and the count still reaches its total.

### L2 (accepted). A joiner shows "starting the search" until judge
The `else` branch that used to send a read report was removed. A check that joins a shared collect now goes from the first gather message straight to `judge`. This matches the stated decision and is not unsafe.

## Areas probed with no finding
- **Order:** `Read` counts and reports under one lock. `work` serializes reports again and drops a lower count in the same stage. The race run is clean.
- **Snapshot fields:** they are added only for `queued` and `running`. Done and error checks are unchanged. The contract change is additive. `message` is reused for running progress and for error sentences, and the docs and the parser separate the two by status.
- **Leaks:** all progress messages are fixed strings or plan names. They carry no URL, key or upstream text. `safeCause` logs only the kind and status, and the test checks that the body is absent.
- **Budget:** `cost.ErrOverBudget` still returns `mapFailure` before the new log line, so the budget refusal behaves as before.
- **CI flake fix:** sound. The test returned while a job it had released on purpose was still running. Waiting for that job to finish is correct, and it does not hide a leak in production code.
- **Outside owns:** only `feedback.md` (the Keel gap and the flake note) and `PHASE-4-server.md` (status and notes) were edited. Both are justified.
- **The four decisions:** none is unsafe or contradicts the spec. All four are accepted.
