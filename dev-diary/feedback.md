# Feedback log

Friction and wins with the services and libraries Before Yes uses, recorded when they were hit. T6.5 drafts the Devpost feedback on Token Factory and the NVIDIA models from this file. Tavily entries support the Best Use of Tavily case.

Each entry gives what happened, the evidence, what it cost, and what would fix it. Never paste a key.

## Apple App Store

- **The customer-review feed went dark with no error and no status change.** `itunes.apple.com/{cc}/rss/customerreviews/.../json` now returns HTTP 200 and a feed skeleton with no `entry` member, which is the same answer an app with no reviews gets. *Evidence:* T0.4 captured 500 reviews per title; later the feed was empty for every app tried, including Facebook (284882215) as a control, in `us`, `gb` and `in`, in the json, xml and no-sort variants, from this machine at two probes and from a separate Hetzner host (T2.3b, [transcript](live/t2.3b-transcript.txt)). The search API still works. *Cost:* the review source the brief rests on is gone, and a client cannot tell a retired feed from a title nobody reviewed, so the pipeline falls back to the App Store web page through Tavily (T3.8). *Fix:* return a 4xx or 410, or an explicit retirement notice, when the feed is withdrawn; or keep serving it.
- **The App Store web page shows only three or four reviews per title, and no rating, date or reviewer name.** A basic Tavily extract of each store page (T3.8a, `testdata/titles/*/tavily-extract-storepage.json`) gives each review's title and body verbatim. It gives no star rating, no review date and no reviewer name, and it repeats each review block. Developer responses keep their own dates. The Editors' Choice blurbs and developer responses are not reviews. The feed fixtures carry rating, date and author on their entries (checked on the first page of Roblox), and none of the four Roblox page reviews appears in them. The demo title Toca Life World is listed on the App Store as "Toca Boca World: Game & Play" (trackId 1208138685), so a lookup by name lands on a different page name. *Cost:* the fallback holds less per review than the feed, and a card cannot cite a rating or date from it. *Fix:* none in our control; the pipeline must dedupe by content, drop the editorial and response blocks, and mark the missing fields absent.

## Tavily

- **Extract credits do not follow the price list, in both directions.** The price list says one credit per five extracted URLs. A two-URL basic extract reported `usage.credits` 0 for Minecraft and 1 for Roblox (T0.4). Later, two-page extracts reported 0 (Khan, Minecraft) while all-failed extracts reported 1 (Roblox, Toca reddit), and a live extract with 1 page read and 2 failed reported 0 (T2.2b) — so the price list would overcount an all-failed extract and undercount a successful one. *Evidence:* the T0.4 MANIFESTs and the T2.2 fixture rows. *Cost:* a meter that prices from the price list drifts from the bill. *Fix:* document the rounding, or report it consistently; the client trusts a genuinely reported `credits` and falls back to the price list only when the number is absent.
- **Single-URL basic extracts of App Store pages report 0 credits on three of four, and repeat the review blocks.** The T3.8a basic extracts reported `usage.credits` 0 for Roblox, Minecraft and Toca Boca World, and 1 for Khan Academy Kids, all one URL and all successful. Each review block appears twice in `raw_content`, and Roblox's "What's New" paragraph appears 26 times. Basic depth gave review text on all four pages, so the advanced depth, which costs more on the price list, was not needed. *Evidence:* `testdata/titles/*/tavily-extract-storepage.json` and their MANIFEST.md T3.8a rows. *Cost:* the meter cannot predict a page's bill, and a parser that trusts `raw_content` counts each review twice. *Fix:* report the credits consistently, and say in the docs that a page's raw text may repeat blocks.
- **A 404 page comes back as a successful extract.** Common Sense `/user-reviews/` URLs that return 404 to a plain GET came back as normal results whose text read "Oops! Looks like that page doesn't exist.", with nothing in `failed_results`. *Evidence:* T0.4b, `tavily-extract-csm-advanced.json` for Roblox and Minecraft. *Cost:* a pipeline would read an error page as a source. *Fix:* put the upstream HTTP status on each result, or route non-2xx pages to `failed_results`.
- **Search on reddit.com returns no raw content** (and a live extract of a reddit thread still fails in T2.2b). `include_raw_content: true` gave `raw_content: null` on all 64 hits, and an advanced extract of the thread URLs failed with "Failed to fetch url" for all 8. Only the `content` snippet is usable. *Evidence:* T0.4a and T0.4b fixtures. *Fix:* say in the docs which domains cannot be fetched.
- **Script-rendered review sections do not come through, even at advanced depth.** Common Sense parent and kid review pages extract only the page heading, a count and a summary. *Evidence:* T0.4a and T0.4b. *Cost:* 20 credits across both probes.
- **No rate-limit headers.** Replies carry only Content-Length, Content-Security-Policy, Content-Type and Date. Nothing reports a window, a remaining allowance or a retry hint, so a client cannot pace itself from the API; it can only pace to the documented figure and react to a 429. *Evidence:* T2.2b, [transcript](live/t2.2b-transcript.txt). *Fix:* send `X-RateLimit-*` and `Retry-After`.
- **A dead host and a blocked site fail the same way.** An extract of a `.invalid` host and of a reddit.com thread both return the bare reason "Failed to fetch url". A client cannot tell a dead link from a site that refuses Tavily. *Evidence:* T2.2b. *Fix:* give `failed_results` a reason code (DNS, refused, blocked, timeout, HTTP status).
- **Works well:** `include_usage` on search and extract makes per-call metering exact, and `include_domains` narrowing works as documented. `include_raw_content` on a basic search costs nothing extra: 1 credit with or without it (T2.2b). It adds about 110 KB for 5 hits, so cap what is kept.

## Keel

- **`throttle.Note` misreports the attempt count when `Transient`/`TransientAttempts` are set** ([nrynss/keel#98](https://github.com/nrynss/keel/issues/98)). Both clients give host faults a smaller retry budget than 429s, so `Note` (which counts `Config.Attempts`) annotates a persistent 500 submitted twice as "still throttled after 4 attempts". *Evidence:* T2.1 and T2.2 round-1 reviews; the clients now annotate the transient case themselves. *Cost:* a misleading error text in the pipeline's failure path. *Fix:* have `Note` report the budget actually spent, or let the caller pass the count.
- **An injected clock gets a private pacer per call.** Any `throttle.Config` that injects `Now` or `Sleep` builds a fresh pacer inside `Retry`, so cross-call pacing is unobservable on a test clock; the pacing tests must sleep for real. *Evidence:* T2.1 and T2.2 reports. *Fix:* keep one pacer per client/key, or expose it for tests.
- **`cost.Meter` cannot drive `cost/sqlitestore.Store`** ([nrynss/keel#99](https://github.com/nrynss/keel/issues/99)). `Store.Reserve/Settle/Release` take a context and a `Reservation` handle, while `cost.Account`'s methods are context-free with no handle, so `cost.NewMeter` cannot wrap the durable store and no adapter ships in v0.7.3. *Evidence:* T2.4 report; `spend` drives the store directly, the path Keel's own `ExampleOpen` documents. *Cost:* each application reimplements reserve-hold-settle-release. *Fix:* give `Store` a `cost.Account` adapter, or give `cost.Meter` a context-and-reservation shape.
- **A reservation lapses after its TTL, which defaults to ten minutes.** `sqlitestore.Config.ReservationTTL` defaults to ten minutes, and an expired hold is purged on the next reserve. `spend` sets it to `spend.DefaultReservationTTL` (30 minutes), so a hold lasts past the longest model call (15 minutes) and a whole fresh check. The hold lasts `ReservationTTL`, set by `spend`. `Settle` on a purged hold still books: `settleBooks` (read from `cost/sqlitestore/sqlitestore.go` source, not exercised by a test) books the spend whether or not the hold row still exists. The remaining risk is only a check that runs past the TTL, which can be overtaken by a second check. *Evidence:* T2.4b, read from source (`defaultReservationTTL`, `purgeExpired`, `settleBooks`); the TTL behaviour is tested in `internal/spend/checks_test.go`. *Fix:* none needed while the TTL exceeds the longest check; a check that must run longer needs a larger `ReservationTTL`.
- **Fixed in v0.7.1–v0.7.3:** cost-store namespaces could not share one file (nrynss/keel#82), and a failed job always carried `job_failed` (nrynss/keel#83). Both were found by this project and fixed upstream.

- **An error event nests the envelope one level deeper than its doc comment suggests.** `wire.ErrorEvent.Error` holds the whole `{"error": {code, message, detail}}` body, so the frame reads `"error":{"error":{...}}`. It is consistent (one parser for responses and events), but easy to document wrongly; T1.4 did. *Evidence:* `testdata/contracts/api/events-error.txt`, written by `wire.WriteEvent` with `wire.NewErrorEvent`. *Fix:* show a full example frame in the `ErrorEvent` doc.

## Token Factory and Nemotron

- **Model ids are case-sensitive, and the listed Nano id has capitals.** The all-lowercase `nvidia/nvidia-nemotron-3-nano-30b-a3b` answers HTTP 404; `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B` works. *Evidence:* `GET /v1/models` on Token Factory and the refusal check in `dev-diary/live/t2.1b-transcript.txt`. *Cost:* a config copied from the brief's lowercase spelling fails every call until someone reads the model list. *Fix:* accept ids case-insensitively, or document the exact spelling.
- **Thinking is on by default and billed as output, about 45x.** The same prompt reports 183 output tokens with no switch and 4 with `chat_template_kwargs.enable_thinking` false ($0.0000467 against $0.0000037 a call on Nano). *Evidence:* the transcript, Token Factory reader and judge. *Cost:* the reader is the high-volume role, so the default is the expensive path. *Fix:* a default of thinking off for a non-reasoning request, or a documented per-model default.
- **`reasoning.enabled` is ignored on Token Factory, and `reasoning_effort` "none" returns empty text.** `reasoning.enabled` off and on report 183 and 178 tokens. `reasoning_effort` "none" cuts the count to 4 but the reply text is empty. *Evidence:* the transcript's sweep lines. *Cost:* a client written for the OpenRouter switch silently leaves thinking on. *Fix:* honour `reasoning.enabled`, or reject unknown fields.
- **OpenRouter ignores `chat_template_kwargs`, and a thinking reply at a small cap is all reasoning.** With `chat_template_kwargs` the reply is 512 tokens and empty text; `reasoning.enabled` false gives 4 tokens and "171". *Evidence:* the transcript, OpenRouter reader. *Cost:* the same settings file does not work across hosts, and an empty reply is easy to read as an outage. *Fix:* one switch across hosts, or an error naming the ignored field.
- **build.nvidia.com lists the Nano id and then 404s it.** `nvidia/nemotron-nano-3-30b-a3b` is in `GET /v1/models` yet a completion answers 404 "Function ... Not found for account"; the body names the account, so the probe withholds it. *Evidence:* the transcript. *Cost:* the brief's reader is not available on the free host, so its reader is the Lightning 30B-A3B, a different model. *Fix:* list only what an account can call.
- **Token Factory also serves `nvidia/Nemotron-3_5-Lightning` and `nvidia/Nemotron-3-Ultra-550b-a55b`.** Four Nemotron ids in all, with inconsistent casing and punctuation (`NVIDIA-Nemotron-3-Nano`, `nemotron-3-super`, `Nemotron-3_5-Lightning`). *Evidence:* the transcript's model list. *Cost:* ids cannot be guessed from each other. *Fix:* one naming scheme.
- **Only Token Factory sends rate-limit headers.** It sends dynamic `X-Ratelimit-*` headers (100 requests and 800000 tokens a minute for the Nano reader, 300 and 200000 for the Super judge, with a dynamic scale and period). OpenRouter and build.nvidia.com send none. *Evidence:* the transcript's rate-limit lines. *Cost:* the pacer's per-minute value comes from one host's headers and is a guess on the others. *Fix:* send the headers on every host, and document a `Retry-After` on 429.
- **Output rate varies by 2.5 times between runs on the same free judge.** OpenRouter's `nvidia/nemotron-3-super-120b-a12b:free` ran at 35 to 43 tokens a second in T2.1b and at about 91 in T2.1c, same `max_tokens` 4000 and thinking on. Nano ran at about 68 and Super at about 156 in T2.1c. *Evidence:* T2.1c measurement, four calls, 4000 output tokens each, rate from `usage.completion_tokens` over wall-clock time. *Cost:* a fixed timeout cannot track the rate, so the client budgets at the slowest rate seen, 30 tokens a second. *Fix:* the host could report time-to-first-token or a queue delay, or the client could stream and watch progress.
- **A call that the host cuts or the client times out may still be billed, and the client has no usage for it.** No reply comes back, so there is no `usage` block. The T2.1c client returns an unmeasured reply priced at the estimate, not zero, and the Keel meter books nothing on a work error, so a caller must book that price itself. *Evidence:* `internal/model` `TestTimedOutCallIsPricedAtEstimateNotZero`; the spend path in `internal/spend/spend.go`. *Cost:* without that, every timed-out thinking call is booked at $0 while Token Factory may bill its written tokens. *Fix:* the host could bill and report partial usage on a closed connection, or Keel's `cost.Meter` could settle at the estimate on a work error that says the call ran.
- **Nano's reader replies run into the 4,096-token cap, and a capped reply is cut mid-JSON.** Across the T3.6b live runs, 15 reader replies came back at exactly `output_tokens` 4096, in both sets. The reader counts a chunk whose reply does not parse as a failed chunk (Token Factory: 4 of 103 chunks; OpenRouter: 11). I did not check each failed chunk against its reply, so the cap is the likely cause, not a verified one. *Evidence:* `testdata/eval/replies/*/reader/*.json` with `"output_tokens": 4096`, and the `failed` column in the T3.6b result note. *Cost:* a chunk's findings are lost whole, and a cut reply is easy to read as a model that found nothing. *Fix:* raise the reader's cap for chunks of this size, or split a chunk when its reply is cut, and count a cut reply under its own reason.
- **The OpenRouter stand-in answered every call without a failure.** 103 reader calls and 6 judge calls per set at the 20-a-minute pace, with no 429 and no 5xx, and the judge's conflict pass ran once per title. *Evidence:* the live summary lines of the T3.6b run (`tools/eval`, `-live-set openrouter`). *Cost:* none in dollars; the stand-in's output is what differs. *Fix:* none needed.
- **No capture covers a list-page alternative.** The alternatives search's list hits ("10 Best Games Like X") now give candidate names from their page text, but the captured fixtures hold no such page, so the parser is tested only on a hand-written stand-in. *Evidence:* `TestListPageEntries`. *Cost:* real list pages may format entries in ways the stand-in does not. *Fix:* capture one list page when live capture is next allowed.
- **List-page entries need a second hit to count.** Neither the shape of a list entry nor its markup tells a title from an advice step or section heading: list pages bold and link both. So an entry becomes an alternative only when the same search response also has a hit titled with that name. *Evidence:* the T3.5 round-4 probe pages, pinned in `TestListPageRejectsHeadingsAndSteps`. *Cost:* a list page adds only picks that the search also found as single-title hits, so it widens recall less than it could. *Fix:* a structured source for "similar titles" (a store's related-apps list) would give names without guessing.
- **The pipeline now calls `BeginCheck`, which PHASE-4 says it does not.** PHASE-4 says "No pipeline code calls `BeginCheck` yet". With the T3.5 user decision, `CheckAlternatives` reserves one check per fresh alternative through `Pipeline.Checks`. The main check's own reservation is still P4's. *Evidence:* `TestFreshAlternativeChecksCountAgainstCap`. *Cost:* if T4.5 wires the main check without setting `Pipeline.Checks`, alternatives run uncapped. If it reserves alternatives itself, they are counted twice. *Fix:* T4.5 sets `Pipeline.Checks` to the same `*spend.Meter` and reserves only the main check.
- **Super ignores "cite the few that decide the area".** Told to cite one to four ids, its first-pass grades still listed 18 to 25 ids per area, mixing stances and sometimes other areas. Under T3.9b's rule (one bad id voids the grade) those flags fall to unknown. *Evidence:* the Roblox first-pass judge recording, `testdata/eval/replies/roblox/judge/`, money, data and content flags. *Cost:* thin areas on every title; the conflict pass, which sees fewer findings, cites tighter.
- **The reader files junk as risk, and a structural citation cannot see it.** Minecraft's developer_record flag cites the stance-risk quote "Explore how we work, what we value, and how we build together.", and the judge's reason says "Mojang Studios has faced regulatory fines", which no cited quote says. The id, area and stance all check out. *Evidence:* T3.9b replay of `testdata/eval/replies/minecraft/`. *Cost:* citation shows the quote beside the grade, but does not make the reason true; it needs an entailment check or a judge reason that must quote.
- **A thinking conflict pass can run to its whole 16,000-token cap.** Minecraft's conflict call came back at exactly 16,000 output tokens; the first-pass grades stood. *Evidence:* Minecraft judge recording, `output_tokens` 16000. *Cost:* about $0.0144 for a discarded pass.
- **Raising the reader cap to 8,192 barely moved output.** Replies at a cap fell from 4 of 103 to 1 of 103, reader output rose 1.2%, and the unquoted-drop rate fell from 23.3% to 21.5% of raw findings; Minecraft also gained 55 bad_area drops. The reader is not deterministic across runs (Roblox unquoted 60 to 67), so a few points of difference is within run noise. *Evidence:* replays before and after.
